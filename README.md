# JSONPlaceholder REST API Automation

Автотесты REST API для открытого тестового сервиса [JSONPlaceholder](https://jsonplaceholder.typicode.com): проверка статус-кодов, структуры и содержимого ответов, создания ресурсов и обработки несуществующих данных.

## Стек

* Java 25, Maven
* TestNG (в том числе SoftAssert)
* RestAssured
* Jackson, Lombok
* JavaFaker
* Aquality Selenium (используется для логирования и чтения настроек)

## Что проверяют тесты

Сценарий `PostTest` покрывает основные операции с ресурсами `posts` и `users`: получение списков и отдельных записей, создание записи и запрос к несуществующему ресурсу. Проверяются статус-коды, структура и содержимое ответов, в том числе сравнение с эталонными данными.

## Архитектура проекта

1. `main/java/api` — классы для работы с API:
   * `BaseApi` — абстрактный базовый класс с настройкой HTTP-клиента.
   * `PostsApi`, `UsersApi` — клиенты для запросов к эндпоинтам.
   * `ApiResponse<T>` — обобщённая обёртка для ответов, которая отвязывает тесты от библиотеки RestAssured.
2. `main/java/models` — POJO-классы для десериализации JSON:
   * `posts` — модель поста (`Post`).
   * `users` — вложенные модели пользователя (`User`, `Address`, `Company`, `Geo`).
3. `main/java/utils` — вспомогательные классы:
   * `ConfigManager` — чтение настроек.
   * `Endpoints` — пути API.
   * `JsonUtils` — десериализация файлов.
   * `RandomUtils` — генерация случайных тестовых данных.
   * `TestDataManager` — загрузка эталонных данных.
4. `test/java/base` — абстрактный класс `BaseTest`, который задаёт базовый URL перед запуском тестов.
5. `test/java/tests` — тестовые сценарии.

## Конфигурация и данные

Настройки и эталонные данные отделены от кода и лежат в `src/test/resources`:

* `settings.json` — настройки фреймворка (параметры Aquality, базовый URL, идентификаторы для тестовых запросов).
* `expectedUser.json` — эталонные данные пользователя для проверки ответа.

## Запуск тестов

Требуется установленный JDK 25 и Maven. Авторизация для JSONPlaceholder не нужна.

**Через IDE (IntelliJ IDEA)**

1. Откройте папку проекта, в которой лежит `pom.xml`.
2. Дождитесь импорта Maven-зависимостей и индексации.
3. Откройте класс `src/test/java/tests/PostTest` и нажмите кнопку Run рядом с названием класса или метода.

**Через терминал**

Перейдите в папку проекта, в которой лежит `pom.xml`, и выполните:

```bash
mvn clean test
```

Если при первом запуске скачивание зависимостей зависло, прервите выполнение и запустите с принудительным обновлением:

```bash
mvn clean test -U
```
